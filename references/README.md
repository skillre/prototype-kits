# Reference Board

> 这里**只存设计参考、截图说明、链接说明和设计语言分析**。
> 不存放、不复制任何受版权保护的大段源码。

---

## 它是干什么的

Agent 在做 Visual Direction 之前，必须先读参考板。目的不是"抄一个好看的页面"，
而是**提取设计语言**，然后用自己的结构重新实现。

```
读 Reference Board  →  提取设计语言  →  写 Visual Manifest  →  做自己的布局
       ↑                                                              │
       └────────────  禁止直接复制别人的页面布局  ←────────────────────┘
```

## 目录

| 目录 | 内容 |
|---|---|
| `editorial/` | 印刷、杂志、年报、编辑式排版的设计语言 |
| `cinematic/` | 深色空间、环境光、电影感产品的设计语言 |
| `instrument/` | 工业仪表、监控终端、工程工具的设计语言 |
| `incoming/` | 还没有归类的参考（正在被分析中） |

## 允许存什么

| ✅ 允许 | 说明 |
|---|---|
| 链接 + 作者 + 一句话说明 | 指向公开页面，不复制内容 |
| 设计语言分析 | "它为什么这样排"——你自己的文字 |
| 结构说明 | 用文字描述布局关系（"左栏固定 320px 导航 + 右栏流式内容"） |
| 颜色关系的描述 | "背景比表面暗两个阶，靠亮度差分层"（不抄 hex） |
| 动效行为描述 | "hover 时 1px 抬升 + 光晕扩散，约 200ms"（不抄代码） |
| 自绘示意图 | 用文字/ASCII/SVG 自己画 |
| 截图（可选的本地引用） | 仅用于内部评审；注明来源与许可状态 |

## 禁止存什么

| ❌ 禁止 | 原因 |
|---|---|
| 复制的外部源码 | 版权风险；且会让 Kits 变成"代码搬运站" |
| 未注明来源的截图 | 无法追溯，等于来源不明 |
| 完整的页面布局（1:1 还原） | 这不是参考，这是抄袭 |
| 需要许可证才能使用但未确认的资产 | 见 `incoming/` 流程 |
| 字体文件 / 图片素材 / 图标包 | Kits 不接受二进制资产依赖 |

## 参考板条目的格式

每条参考都用同一个格式，便于 Agent 解析：

```markdown
### <标题>

- **来源**：<链接>
- **作者 / 组织**：<名称>
- **类型**：<landing / dashboard / report / tool / editorial>
- **许可状态**：<仅参考 / CC-BY / 未确认>

#### 提取的设计语言

1. **层级**：<它用什么建立层级？字号/空间/光/线？>
2. **节奏**：<间距脉搏多大？段落间距与内边距的关系？>
3. **排版**：<衬线还是无衬线？字距正还是负？行高多少？>
4. **边界**：<用线还是用盒子还是不用？>
5. **表面**：<平面/纸/玻璃/发光？>
6. **动效**：<动什么？多快？触发条件？>
7. **可借鉴**：<具体哪一条可以迁移>
8. **不可借鉴**：<哪一条不该迁移，为什么>

#### 不要复制的地方

<明确指出哪些部分属于对方的版式/品牌识别，不应出现在我们的产物里>
```

## 使用纪律

1. **读参考 → 写 Manifest → 才允许写代码。** 顺序不可交换。
2. 每条参考必须写清 **可借鉴** 与 **不可借鉴** —— 后者同样重要。
3. 借鉴的是**语言**（语法与词汇），不是**句子**（具体布局）。
4. 任何来自外部、准备进入 Kits 的**代码资产**，一律走 `incoming/` 流程：
   `inspect → license/source check → dependency audit → compatibility audit → normalize → adapter → fallback → demo → test → experimental → approved`。
5. 参考板里的条目**不是资产**，它们不出现在 `registry/assets.json` 里 ——
   登记表只登记可以被产品引用的东西。
