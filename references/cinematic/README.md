# Reference Board · cinematic

> 深色空间、环境光、电影感产品的设计语言。
> 本文件**只做设计语言分析**，不含任何外部源码。

---

## 设计语言的四个来源

### 1. 电影摄影的「三点布光」

传统布光是主光（key）+ 辅光（fill）+ 轮廓光（rim）。它建立了"这个东西在空间里"
的感知，而不是把它画在平面上。

- **提取**：`.kits-ambient` 用三个**有方向**的径向光源：左上主光（青）、
  右上辅光（琥珀）、底部补光（紫）。关键在"有方向"—— 无方向的背景渐变
  会让页面看起来是"贴了一张图"。
- **不可借鉴**：真实布光的强度比例（银幕上的对比度放到屏幕上会让文字不可读）。
  这里所有光的不透明度都 ≤ 0.16。

### 2. 影院空间感的「景深」

观众感知到"纵深"，靠的是远处的东西更暗、更虚、更小。

- **提取**：进入动效带 **24px 位移 + 6px 模糊** —— 从虚到实 = 从远到近。
  配合 `--kits-reveal-blur`，cinematic 的 reveal 是唯一有模糊的 pack。
- **不可借鉴**：真实景深的虚化范围（屏幕上超过 8px 的模糊会让文字无法阅读）。

### 3. 深色产品页的「表面亮度梯度」

深色界面里，"更重要的区块"不能靠加边框 —— 边框在深色下会变成调试框。
它们靠**比背景亮一点点**。

- **提取**：`canvas #07090f` → `surface #0f1420` → `raised #161d2c`。
  每一层比上一层亮约 6–8%。**这就是层级。**
- **不可借鉴**：把梯度做成"每层加 20% 亮度"——那样会得到一堆灰色块。

### 4. 金融终端的「只让数据发光」

深色数据界面里，颜色是最稀缺的资源。好的终端只让**当前焦点**的数据发光，
其余一切灰阶。

- **提取**：同屏发光元素 ≤ 1；网格线只有 7% 白；正文用 `ink-muted` 而不是 `ink`。
- **不可借鉴**：多色霓虹。那会让"哪个数字重要"这个问题无法回答。

## 关键数值关系（cinematic 的"语法"）

| 关系 | 值 | 为什么 |
|---|---|---|
| 标题行高 | **1.08** | 比 editorial（1.02）松 —— 光晕需要呼吸 |
| 标题字距 | **+0.005em** | **正字距**：深色下收字距会让字粘连 |
| 字重 | **≥ 500** | 400 字重会被深色背景吃掉 |
| 正文颜色 | `ink-muted` | 只有标题用 `ink` —— 靠这个差值建立阅读层级 |
| 圆角 | **14px**（surface） | 连续的大半径，让光沿边缘爬 |
| 边框 | **0** | 区块靠亮度差分开；需要边界时用 1px 白 9% 的"光边" |
| 网格线 | **7% 白** | 极淡：它是空间暗示，不是结构 |
| 间距脉搏 | **8px**，段落 96px | "层"的节奏：层级内紧、层级间松 |

## 视觉签名（三个一眼可辨的动作）

1. **一片有方向的环境光**（不是均匀的深色背景）。
2. **玻璃表面 + 内高光 + 深投影**（表面浮在空间里）。
3. **发光的曲线与端点光点**（数据是光的载体）。

## 反模式（cinematic 最常被做坏的方式）

| 反模式 | 结果 |
|---|---|
| 纯白 `#fff` 配纯黑 `#000` | halation：文字边缘发虚 |
| 给每个卡片加 glass | 深度失效（全是玻璃 = 没有对比） |
| 无方向的渐变背景 | 从"空间"退化成"贴了一张图" |
| 深色 + 400 字重正文 | 文字发灰、发虚 |
| 多个同时发光的元素 | 焦点消失 |
| 大元素回弹缓动 | 视觉晕眩 |
| 用边框（1px #333）分区 | 页面变成深色表格 |
| 紫色渐变铺满 | 那是"科技风模板"，不是电影感 |

## 与其它 pack 的区分点（灰度化后仍可见）

| 对比 | cinematic | 另一个 pack |
|---|---|---|
| vs editorial | 圆角 14px、有投影、有光、导航浮起、段落 64px | 方角、无投影、纸纹、导航是书眉行、段落 96px |
| vs instrument | 60–64px 网格、55% 淡出、字距正、无边框、发光 | 32px 网格、22% 淡出、处处 1px 边界、无发光 |
