## 0 · 先说清楚这份参考板的诚实边界

**本案没有做外部参考分析。** `console` 的方向不是从公开作品里提取出来的，它来自
**本案自己的设计稿**（工作区根目录的 `.pen` 与 `S1-设计稿实测与实现规格.md`，391 个节点实测）。

所以这份文档里：

- **有实测出处**的写实测值（76 / 130 / 500 / 600 / 366 / 38 / 28 …），出处是设计稿；
- **谱系**部分（§1）写的是"它读起来像什么传统"——那是**辨认**，不是声称当初照着它做的；
- **外部参考：未做**。这对一套要投屏给领导看的界面是个真实风险（单一来源 = 没有对照物），
  补救方式写在 §6。把它写在这里而不是省略，是因为"没有参考"和"参考了但没记"是两件事，
  后者会在下一次被人误当成前者。

## 1 · 谱系：它为什么读起来像"控制台"

四条传统，都是**语言**层面的（借语法，不借句子）：

### 1. 交易大厅与运营控制台（terminal / trading desk）

密集等宽读数、单元格化的数字区、颜色只用来表示状态。**层级靠位置和分隔，不靠卡片**。
可借鉴的一条：一个读数占一格、彼此等宽对齐 —— 数字的**数位对齐**本身就是可读性。
不可借鉴的一条：专业终端的"多窗口堆叠 + 窗口标题栏"，那是软件史的包袱，不是语言。

### 2. 值班室与操作规程（operations bridge / runbook）

大屏上最重要的不是信息多，而是**"现在该谁动"**：进行中的事件、等谁授权、SLA 还剩多久。
可借鉴的一条：把"待人"和"待机器"分开摆，并且**让等待有倒计时**。
不可借鉴的一条：值班室的物理布局（成排工位、抬头显示），不要变成装饰性模仿。

### 3. 日志与流水（log viewer / stream）

一行一条事实，新的在下（或在上）、可回溯、可定位到出处。
可借鉴的一条：**每一条都带得回出处**（事件号 / 证据号），这是"可追问"的界面形态。
不可借鉴的一条：把日志做成"无限滚动的黑底绿字"——那是气氛，不是界面。

### 4. 工业仪表与航空读数（instrument / annunciator）

指示灯矩阵的语义纪律：**一个颜色一个含义，且含义不随上下文漂移**。
可借鉴的一条：颜色是判据（红=攻击、青=AI 在跑、琥珀=等你、绿=已闭环）。
不可借鉴的一条：拟物化的仪表盘纹理、刻度圈、发光灯珠。

## 2 · 数值语法（console 的"句子结构"）

| 关系 | 取值 | 为什么是这个数 |
|---|---|---|
| 画布 | 1680×1050 | 16:9 单屏不滚动；缩放由产品侧的 `scale-to-fit` 负责 |
| 分栏 | 500 / 600 / 366 | 左"实体" / 中"战情" / 右"信任"——中列最宽，因为结论在中列 |
| 分隔 | 1px 规则线 + 亮度差 | **不用边框分层**：盒子会把密度压回普通 SaaS |
| 顶栏 | 76px（44 控件 + 2×16） | 命令条是一行，不是一个 hero |
| 底栏 | 130px（4×28 + 18） | 4 行日志是"够用且不抢戏"的量 |
| 圆角 | 近 0 | 终端里没有圆角 |
| 字体 | 全站等宽（含结论级 28–36px） | 等宽让数字与代码在**同一根网格**上 |
| 动效 | 50–220ms，只表达状态变化 | 见 §4 |

---

## 3 · 视觉签名（三个一眼可辨的动作）

1. **一条规则线切开的三个世界**：左实体、中战情、右信任。灰度化后仍然成立。
2. **划掉重写**：计划被重规划时，旧的一行**留着并划掉**，新的一行在旁边出现 ——
   "AI 改了主意"这件事必须看得见，而不是被静默替换。
3. **逐字打出 + 逐行回显**：命令与回显都作为**事实行**留在控制台里，带退出码。

---

## 4 · 动效纪律（这套 pack 最容易做坏的地方）

只允许表达**状态变化**的动效：流式打字、呼吸点、粒子汇流、碎裂盖戳、划掉重写。
时长窗口 50–220ms。**禁用无意义入场动画**——"需要解释才看得懂的动效 = 失败的动效"。

反模式：环境光呼吸、扫描线、粒子地球、数字雨。它们会让界面看起来像"展厅大屏"，
而那正是这套风格**明确要区分开**的东西（`darkDirection` 与 `materialDirection` 里
`ambient` 不授权、`glow` 无预算，是硬门而不是建议）。

## 5 · 与其它三套 pack 的区分点（灰度化后仍可见）

| | 建立层级的方式 | 灰度下靠什么分辨 |
|---|---|---|
| `editorial` | 字号级差 + 大量留白 | 大标题与正文的字号比、行宽窄 |
| `cinematic` | 环境光 + 景深 | 亮度渐变的层次 |
| `instrument` | 刻度与指针式的重复结构 | 均匀重复的小结构 |
| **`console`** | **1px 规则线 + 亮度差 + 等宽网格** | **竖线切分与等宽对齐** |

`console` 在灰度下**丢不掉**的正是那几条竖线：把颜色全部拿掉，三列依然分得开。

## 6 · 没做的事（以及怎么补）

| 没做 | 影响 | 补救 |
|---|---|---|
| 外部参考分析 | 方向只有单一来源（本案设计稿），没有对照物；3 米可读性、密度上限都没有外部锚点 | 下一个用 `console` 的产品在写 Visual Manifest **之前**，先按本仓 `references/README.md` 的条目格式补 2–3 条真实外部参考（交易终端 / 值班室 / 日志查看器各一），并写清"不可借鉴" |
| 截图与许可记录 | 无法追溯 | 同上：只存链接 + 自己的分析，不复制内容 |
| 灰度快照 | 上表的"灰度下仍可分辨"目前是**推理**，不是实测 | 用 `pnpm qa` 的 style-presence 通道加一档灰度断言（`grayscale(1)` 下三列规则线仍可见） |

> 参考板条目**不是资产**：它们不出现在 `registry/assets.json` 里，产品也不能 import 它们。
